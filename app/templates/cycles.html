A unit teaches you one detection on a fixture that already has an answer. A cycle points that same skill at a real system. Nobody has graded that system for you. You commit what you think is wrong with it before you measure. Then you find out how close you were.

What a target is

Any AI system you can actually run and measure, that you did not write. In practice that means one of:

  • an open-source RAG or agent repo you can clone and get running locally
  • a system at work you have access to, which is the one that pays off fastest
  • a hosted API you can send a few hundred requests to

The constraint that matters is not how interesting the system is. It is whether you can run it enough times to measure something. A system you can only read is a system you can only have opinions about, which is the habit this is meant to replace.

What one looks like, start to finish

Target an open-source RAG starter repo, cloned and running locally.

Question under test an interviewer would ask you this question, and you could not answer it today. Something like: does retrieval hold up on questions that need two facts, or does it only look good on the easy ones?

Your prediction, sealed before you measure in your own words, plus the number that would prove you wrong. For example: this pipeline embeds each chunk on its own and never decomposes the query. So a multi-hop question retrieves one hop and misses the other, and recall_at_5 comes in below 0.6. You say how confident you are, maybe 0.75. Then you seal, which hashes the claim and commits it to git so the timestamp is not just your word.

Then you measure. Write 40 or 50 questions that need two facts. Run them through the system. Compute recall_at_5 with the same library function unit 08 gave you, then post the number.

Then you find out if it came in at 0.42 you were right, and your 0.75 confidence was well placed. If it came in at 0.71 you were wrong, and being 75 percent sure about it costs you more than being unsure would have. Either way you get a teardown you can publish, with the numbers and the seal in it.

Before you start one

Two honest warnings. The first is that the measurement is the work. You will spend an evening or two to get another person's system to run and to build an eval set for it. That is most of the value, not overhead.

The second is to do a couple of units first. They teach you which detections exist, and that is what tells you what to predict. If you start here with no units behind you, you will face a form with nothing to write in it.
